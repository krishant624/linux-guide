    Linux Guide: Beginner to Confident

    A friendly, practical path from “I’ve never used a terminal” to navigating files, permissions, packages, processes, networking, simple scripts, and real troubleshooting—mostly on Ubuntu/Debian, with Fedora/RHEL notes when commands differ.

    Live: krishant624.github.io/linux-guide

    Practice in a VM / WSL Examples + common mistakes Exercises with answers
    Warning

    Practice in a virtual machine, WSL, live USB, or disposable cloud instance. Some commands can delete data or break a system. Never experiment with rm -rf, dd, or mkfs on a machine you care about.

    1. What Linux is

    Why it matters: “Linux” usually means the kernel plus a distribution (Ubuntu, Fedora, Debian…) that packages apps, an installer, and tools around it.

    • Open source: you can inspect and share most of the system software.
    • vs Windows/macOS: stronger terminal culture, package managers instead of random installers, clearer separation of system vs user files.
    • Common distros: Ubuntu/Debian (apt), Fedora/RHEL/Rocky (dnf), Arch (pacman).
    Common mistake

    Thinking “Linux” is one product. Always note which distro and version when following tutorials (e.g. Ubuntu 24.04).

    2. Getting started

    Pick one playground:

    • WSL2 on Windows — easiest if you already use Windows: wsl --install then choose Ubuntu.
    • VirtualBox / VMware / Hyper-V / UTM — full VM; safest for disk experiments.
    • Live USB — try without installing.
    • Cloud VM — DigitalOcean, AWS, Azure free tiers; login with SSH.

    How you’d use this

    On Windows: install WSL Ubuntu → open “Ubuntu” from the Start menu → you land in a bash prompt as your Linux user. On a cloud VM: create the instance, download the SSH key, then ssh user@ip.

    $ whoami
$ uname -a
$ cat /etc/os-release
    krishant
Linux hostname 6.8.0-… #… SMP … x86_64 GNU/Linux
PRETTY_NAME="Ubuntu 24.04.1 LTS"
…
    Tip

    Write down your username and whether you have sudo. You’ll need both constantly.

    3. The terminal and shell

    The shell (usually bash) reads what you type. Structure: command options arguments.

    $ ls -la /home
$ man ls
$ ls --help
$ history | tail -n 5
    • Tab — complete names; press twice to list matches.
    • Up/Down — previous commands; Ctrl+R search history.
    • Ctrl+C cancel; Ctrl+L or clear clear screen; Ctrl+D end input / exit.
    Common mistake

    Typing spaces in filenames without quotes. Prefer mkdir "My Notes" or avoid spaces: my-notes.

    Try it yourself

    Run echo hello, then man echo (quit with q). Use Tab to complete a long directory name under /usr.

    Show expected ideas

    You should see hello, a man page, and tab completing something like /usr/share.

    4. Filesystem layout

    $ pwd
$ cd ~
$ cd /
$ ls -la
$ cd /var/log
$ cd -

    Absolute paths start with /. Relative paths start from your current directory. ~ is your home; .. is parent; . is current.

    Common mistake

    Confusing /home/you with /. Deleting under / as root can destroy the OS. Stay in your home while learning.

    5. Working with files and directories

    $ mkdir -p ~/learn/linux
$ cd ~/learn/linux
$ touch notes.txt
$ cp notes.txt notes.bak
$ mv notes.bak backup.txt
$ ln -s notes.txt notes-link
$ ls -l
$ find ~ -name '*.txt' 2>/dev/null | head
    • Symbolic link (ln -s) — shortcut to another path.
    • Hard link — another name for the same file data (same filesystem).
    • Wildcards: * any chars, ? one char, *.log pattern.
    Warning

    rm -rf directory deletes recursively with no trash. Prefer rm file, double-check paths, or move to a trash folder while learning. Never run rm -rf /.

    How you’d use this

    Organizing homework: mkdir -p ~/school/math, copy reports with cp report.pdf ~/school/math/, rename with mv, find lost files with find ~ -iname '*budget*'.

    Try it yourself

    Create ~/learn/demo, three empty files, copy one, rename one, make a symlink, list with ls -l.

    Show a sample solution 
    $ mkdir -p ~/learn/demo && cd ~/learn/demo
$ touch a.txt b.txt c.txt
$ cp a.txt a-copy.txt
$ mv b.txt b-renamed.txt
$ ln -s a.txt a-link
$ ls -l

    6. Viewing and editing text

    $ echo 'line one' > hello.txt
$ echo 'line two' >> hello.txt
$ cat hello.txt
$ less /etc/hosts
$ head -n 5 /etc/passwd
$ tail -n 5 /etc/passwd
$ nano hello.txt

    nano: easy—Ctrl+O save, Ctrl+X exit. vim survival: i insert, Esc, :wq save+quit, :q! quit without saving.

    Common mistake

    Stuck in vim and panicking. Press Esc, type :q!, Enter. You’re out.

    7. Searching and processing text

    Pipes send one command’s output into the next. Redirection writes to files.

    $ grep -n root /etc/passwd
$ cut -d: -f1 /etc/passwd | sort | uniq | wc -l
$ dmesg 2>/dev/null | tail -n 20 | tee ~/dmesg-tail.txt
$ printf 'b\na\nc\na\n' | sort | uniq -c
    • > overwrite file, >> append, 2> stderr, | pipe, tee view and save.
    • sed stream edits; awk columns/patterns—learn gradually.

    How you’d use this

    Find failed logins: grep -i failed /var/log/auth.log (Ubuntu) or journalctl -u ssh -g failed.

    Tip

    Build pipelines one step at a time. Run the left half, then add the next |.

    Try it yourself

    List usernames from /etc/passwd (field 1), sort them, and count how many.

    Show answer
    $ cut -d: -f1 /etc/passwd | sort | wc -l

    8. Users, groups, and permissions

    $ whoami
$ id
$ ls -l hello.txt
$ chmod u+x hello.txt
$ chmod 644 hello.txt
$ sudo -v

    Permission triad: user / group / others, each rwx. Octal: 4=r, 2=w, 1=x → 755 or 644 common.

    -rw-r--r-- 1 you you 12 Mar 20 10:00 hello.txt
# type  user  group  others
# -     rw-   r--    r--
    Warning

    Avoid chmod -R 777. It makes files world-writable and is a security smell. Prefer the least permission that works.

    Common mistake

    Using sudo for everything. Prefer your user; elevate only when editing system files or installing packages.

    How you’d use this

    Script won’t run? chmod u+x script.sh then ./script.sh. Need to edit nginx config? sudo nano /etc/nginx/nginx.conf.

    9. Package management

    Ubuntu / Debian (apt) 
    sudo apt update
sudo apt upgrade
apt search htop
sudo apt install htop
sudo apt remove htop
    Fedora / RHEL (dnf) 
    sudo dnf check-update
sudo dnf upgrade
dnf search htop
sudo dnf install htop
sudo dnf remove htop
    $ sudo apt update
$ sudo apt install -y tree
$ tree --version
$ which tree

    Also: snap/flatpak for sandboxed desktop apps. Prefer distro packages for system tools.

    Common mistake

    Installing random .deb files from the web without need. Prefer apt/dnf so updates stay consistent.

    10. Processes and services

    $ ps aux | head
$ uptime
$ systemctl status ssh || systemctl status sshd
$ journalctl -u ssh -n 20 --no-pager
$ sleep 300 &
$ jobs
$ kill %1
    • systemctl start|stop|restart|enable|disable SERVICE
    • Cron: crontab -e for user schedules; systemd timers are the modern alternative.
    Warning

    kill -9 is last resort. Try normal kill PID first so apps can exit cleanly.

    11. Disks and storage

    $ lsblk
$ df -h
$ du -sh ~/*
$ mount | head

    /etc/fstab mounts filesystems at boot. LVM adds flexible volumes on top of disks. Common FS: ext4 (Ubuntu), XFS (many RHEL setups).

    Warning

    mkfs, fdisk, parted, and wrong dd targets can wipe disks. Practice only inside a throwaway VM with a second virtual disk.

    Common mistake

    Reading df “100% full” on / and ignoring du to find the fat directory—often logs under /var/log.

    12. Networking

    $ ip a
$ ping -c 3 1.1.1.1
$ ss -tulpn | head
$ curl -I https://example.com
$ ssh-keygen -t ed25519 -C 'linux-guide'

    Copy a key to a server: ssh-copy-id user@host. Copy files: scp file user@host: or rsync -avP dir/ user@host:dir/.

    Ubuntu firewall
    sudo ufw allow OpenSSH
sudo ufw enable
sudo ufw status
    Fedora firewall
    sudo firewall-cmd --permanent --add-service=ssh
sudo firewall-cmd --reload
firewall-cmd --list-all
    Common mistake

    Enabling a firewall before allowing SSH on a remote VM—and locking yourself out. Always allow SSH first.

    13. Shell scripting

    $ cat > ~/learn/hello.sh <<'EOF'
#!/usr/bin/env bash
set -euo pipefail
name=${1:-friend}
echo "Hello, $name"
EOF
$ chmod u+x ~/learn/hello.sh
$ ~/learn/hello.sh Linux
    Hello, Linux

    Useful: if/then/fi, for f in *; do …; done, functions, $# argc, $? exit code. set -euo pipefail makes scripts fail fast on errors.

    Practical mini-script idea

    Backup a folder: tar -czf backup-$(date +%F).tar.gz ~/Documents inside a script run by cron.

    Tip

    Test scripts on junk data first. Quote variables: "$file".

    Try it yourself

    Write a script that prints the current date and disk usage of your home (du -sh ~).

    Show a sample script 
    #!/usr/bin/env bash
set -euo pipefail
echo "Date: $(date)"
du -sh "$HOME"

    14. Environment

    $ echo $PATH
$ echo $HOME
$ export DEMO=1
$ echo $DEMO
$ alias ll='ls -alF'
$ grep -n alias ~/.bashrc || true

    Put lasting aliases/exports in ~/.bashrc (interactive bash) or ~/.profile. Then source ~/.bashrc.

    Common mistake

    “Command not found” after installing something—often the shell session needs a restart, or the binary isn’t on PATH (which tool, echo $PATH).

    15. Archiving and compression

    $ tar -czf learn-backup.tar.gz -C ~ learn
$ tar -tzf learn-backup.tar.gz | head
$ mkdir -p /tmp/restore && tar -xzf learn-backup.tar.gz -C /tmp/restore
$ zip -r notes.zip ~/learn/linux
$ unzip -l notes.zip | head

    Remember: c create, x extract, t list, z gzip, f file.

    16. Logs and monitoring

    $ journalctl -xe --no-pager | tail -n 30
$ sudo dmesg | tail -n 20
$ free -h
$ uptime
$ ls /var/log | head

    Triage order: what changed? disk full? OOM (memory)? service logs via journalctl -u name.

    How you’d use this

    Web server down → systemctl status nginx → journalctl -u nginx -n 50 → df -h if it mentions no space.

    17. Security basics

    • Least privilege: normal user daily; sudo only when needed.
    • Keep packages updated (apt upgrade / dnf upgrade).
    • SSH keys over passwords; disable password login only after keys work.
    • fail2ban (optional): bans IPs after repeated SSH failures.
    Tip

    On cloud VMs, restrict SSH in the cloud firewall + ufw/firewalld. Don’t expose unnecessary ports.

    19. Practice & capstone

    Warm-ups

    Exercise A — Home lab folder

    Create ~/linux-lab/{inbox,outbox,scripts}, a notes file, and a symlink from inbox to notes. List with ls -lR.

    Exercise B — Log detective

    Use journalctl -n 100 --no-pager and count how many lines contain error case-insensitive (grep -ci error).

    Exercise C — Mini backup script

    Script that tars ~/linux-lab into ~/backups/lab-YYYY-MM-DD.tar.gz and prints the file size.

    Sample solution 
    #!/usr/bin/env bash
set -euo pipefail
mkdir -p "$HOME/backups"
stamp=$(date +%F)
out="$HOME/backups/lab-$stamp.tar.gz"
tar -czf "$out" -C "$HOME" linux-lab
du -h "$out"

    Capstone project

    Build a personal “sysadmin starter kit” on your VM:

    1. Create a non-root workflow you understand (sudo when needed).
    2. Install htop, tree, curl.
    3. Write ~/bin/sysreport.sh that prints: date, uptime, df -h, free -h, and last 10 journal lines; make it executable; add ~/bin to PATH in ~/.bashrc.
    4. Create a weekly cron or document how you’d schedule it.
    5. Optional: enable ufw/firewalld with SSH allowed.
